# GMF-007 — Form section (PO-N3, D-068)

**Status**: completed 2026-08-22. Submission 1 via PR #37 (merge commit
`56398e9`, base `staging`); the section then rode the D-084 redesign — it
lives in the batter detail dialog (Sluggers and Matchups row selections),
joined by the D-084/D-086 field panel and exit-velocity log (PRs #40, #41).

## Delivered

- `greenmachine.live.form` — `FormSection`/`FormValue`: the seven-metric
  recent-form read (Barrel%, EV, AtkAng, IdealAtkAng%, Pull Air %, Hard%,
  xwOBA) with per-metric L7→L14 window resolution against per-metric floors
  (D-068), already landed under GMF-006's pipeline.
- `streamlit_app.py` — `_form_section_frames`: the section's cell rules as
  display text (D-076): present-and-sufficient is the plain value; an L14
  fallback names its window (`· L14`); a below-floor L14 keeps its value,
  exact sample and INSUFFICIENT marker on opaque amber; no observations at
  either reach reads "not enough data available" in muted italics (D-078
  wording). Pull% is labelled Pull Air % per the ticket text.
- The selection surface: both Sluggers and Matchups grids are
  single-row-selectable; one `st.dialog` opens after the tabs with the
  selected card, and an epoch in the grid keys makes dismissing the dialog
  stick (Streamlit re-runs on dismiss would otherwise reopen it).
- Tests: the cell rules as ordinary code (`tests/app/test_form_section.py`),
  the board render with selectable grids, and the dialog body via
  `tests/app/runners/run_form_section.py` plus browser screenshots (AppTest
  has no row-selection API or dialog driver at the pinned runtime).
